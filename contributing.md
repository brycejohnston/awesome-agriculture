# Contributing Guidelines

Know another awesome API, project, library, app, or tool that is missing from this list? Open a pull request or file an issue. Everyone's contributions are always welcome!

## Guidelines

- Add one resource link per contribution pull request. Keep maintenance and formatting changes separate from new suggestions. Maintainers may consolidate already reviewed suggestions and related cleanup into a clearly documented maintenance PR.
- Use this format:
  `- [project-name](https://example.com/) - A short, factual description.`
- Link to the official repository or project website. Open source software should have an explicit license; datasets should state their sources and reuse terms. A free website alone does not establish that a resource is open source.
- Search the existing list, issues, and pull requests before suggesting a resource to avoid duplicates.
- Put the resource in the most relevant section and sort entries alphabetically by their displayed names, ignoring case.
- Put country and location-specific reference datasets under the appropriate country in **Datasets > Regional Data**. Keep research datasets and broadly applicable collections under **Research and General Data**.
- Add a section only if needed. Match the existing Markdown heading levels, add a short description, and update the table of contents.
- Keep descriptions concise and accurate. Identify projects that are in development and distinguish local functionality from optional hosted or paid services.
- Verify that links work and still point to the intended project. Prefer a current official destination over an outdated redirect.
- Check spelling and grammar, and remove trailing whitespace.
